## 🔍 Пошаговая проверка:

### 1. Проверка файлов в репозитории

Убедитесь, что все файлы закоммичены и запушены:

```bash
git status
git log --oneline -3
```

Должны быть видны:
- `.github/workflows/deploy.yml`
- `public/404.html`
- Обновленный `vite.config.ts`
- Обновленный `src/main.tsx`

### 2. Проверка настроек GitHub Pages

1. Перейдите в репозиторий на GitHub: `https://github.com/IrinaTitovich/master-marks`
2. Откройте **Settings** → **Pages**
3. В разделе **Source** должно быть выбрано: **GitHub Actions** (НЕ "Deploy from a branch")
4. Если там выбрана ветка - измените на **GitHub Actions**

### 3. Проверка GitHub Actions

1. Перейдите в раздел **Actions** вашего репозитория
2. Должен быть виден workflow "Deploy to GitHub Pages"
3. Если есть ошибки - откройте workflow и проверьте логи:
   - Проверьте шаг "Build" - должна быть успешная сборка
   - Проверьте шаг "Deploy to GitHub Pages" - должен быть успешный деплой

### 4. Проверка URL сайта

После успешного деплоя сайт должен быть доступен по адресу:
```
https://irinatitovich.github.io/master-marks/
```

**Важно:** Обратите внимание на `/master-marks/` в конце URL!

### 5. Проверка работы сайта

Откройте сайт и проверьте:

- [ ] Главная страница загружается
- [ ] Стили применяются корректно
- [ ] Изображения отображаются
- [ ] Навигация работает (переходы между страницами)
- [ ] Прямые ссылки на страницы работают (например, `/master-marks/projects`)
- [ ] Нет ошибок в консоли браузера (F12 → Console)

### 6. Типичные проблемы и решения

#### Проблема: Сайт показывает 404 или пустую страницу

**Решение:**
- Проверьте, что в Settings → Pages выбран источник **GitHub Actions**
- Проверьте, что base path в vite.config.ts правильный (`/master-marks/`)
- Проверьте логи GitHub Actions на наличие ошибок

#### Проблема: Стили не загружаются / белая страница

**Решение:**
- Откройте консоль браузера (F12) и проверьте ошибки
- Проверьте, что пути к ресурсам правильные (должны начинаться с `/master-marks/`)
- Убедитесь, что `base: '/master-marks/'` установлен в vite.config.ts

#### Проблема: Роутинг не работает (404 при переходе на страницы)

**Решение:**
- Проверьте, что файл `404.html` находится в `public/` и копируется в `dist/`
- Проверьте, что `404.html` содержит правильный base path (`/master-marks`)
- Проверьте, что в `src/main.tsx` есть обработка редиректа из 404.html

#### Проблема: GitHub Actions не запускается

**Решение:**
- Убедитесь, что файл `.github/workflows/deploy.yml` существует и закоммичен
- Проверьте синтаксис YAML файла (можно проверить через GitHub UI)
- Убедитесь, что у репозитория есть права на GitHub Pages (Settings → Pages)

#### Проблема: Сборка падает с ошибкой

**Решение:**
- Проверьте логи GitHub Actions в разделе "Build"
- Убедитесь, что `package.json` содержит все необходимые зависимости
- Проверьте, что Node.js версия совместима (в workflow указана версия 20)

### 7. Локальная проверка сборки

Для проверки сборки локально (опционально):

```bash
# Установите зависимости (если еще не установлены)
npm install

# Соберите проект
npm run build

# Проверьте содержимое dist/
# Должны быть файлы с правильными путями (начинающимися с /master-marks/)
```

### 8. Проверка структуры dist после сборки

После сборки в папке `dist/` должны быть:
- `index.html`
- `404.html` (скопирован из public/)
- `assets/` (JS, CSS файлы)
- Все статические файлы из `public/`

В `index.html` пути к ресурсам должны начинаться с `/master-marks/`, например:
```html
<script type="module" src="/master-marks/assets/index-xxx.js"></script>
```
